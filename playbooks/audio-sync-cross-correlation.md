# 音频互相关对齐

**适用场景：** 两段视频内容相同，但起点不同，比如 AI 重绘版和原版、二次剪辑版和原片、分段文件和整段转写。需要知道它们差多少秒，以及有没有越播越偏。

**为什么用音频：** AI 重绘、调色、裁切都会改变画面，但很少动音轨。音频采样率高（8–16 kHz），定位精度可以到毫秒级，而视频帧间隔有 33 ms。

## 方法

1. 两路都解码成**单声道 float PCM**，8 kHz 够用；要做精细复核时用 16 kHz。
2. **全局粗定位：** 拿短的一路（或其中一段）当模板，对长的一路做 FFT 互相关。
3. **一定要归一化：** 用长的一路的**局部能量**做归一化（NCC，1.0 表示完全相同），并且**屏蔽能量很低的区段**。否则静音段或音量大的段落会“抢”到峰值。项目 01 第一次分析时就踩过这个坑：没有归一化，所有窗口都错误地匹配到了片尾。
4. **滑窗复核：** 用 1.5–3 秒的窗口，每隔 0.5–10 秒滑动，逐窗求偏移。
   - 所有窗口偏移相同：对齐干净。
   - 偏移线性变化：两路速度不同（帧率或采样率换算问题）。
   - 个别窗口 NCC 很低：这一段不在对方里（被剪掉、替换或配乐不同）。
5. **用画面交叉验证：** 把两路视频缩到 64×36 灰度，算帧差信号再做相关；同时对照镜头切点，拼几组对照帧肉眼看。
6. **渲染后复测：** 成片再和基准做一次互相关。项目 02 复测的残差是 7 ms。

## 工具

[`tools/av/find_offset.py`](../tools/av/find_offset.py)：通用版，输出每个窗口的偏移、NCC，以及中位数和离散度。

```bash
# 某段素材在整片里的位置（项目 02：卡通版在 MV 里）
python3 tools/av/find_offset.py cartoon.mp4 mv.mkv --sr 16000 --win 1.5 --step 0.5

# 拼接版由哪些片段组成（项目 01：方案四在拼接版里的偏移）
python3 tools/av/find_offset.py plan4.mp4 merged.mp4 --step 10
#   → median offset 67.9334s  spread 0.0000s
```

## 把偏移用到 ffmpeg 里

| 需求 | 写法 |
|---|---|
| 晚开始的一路，开头补帧 | `tpad=start_duration=0.0407:start_mode=clone` |
| 音频延后，按采样点 | `adelay=1954S:all=1`（0.0407 s × 48 000） |
| 从某个时间点开始截取 | `-ss <offset>` 放在 `-i` 前面，先快速定位 |
| 分段文件映射回整片时间 | `part_time = abs_time − part_start + AUDIO_OFFSET`（项目 03） |

## 来源

- 项目 02：卡通版 = MV 的 0:00–0:23，偏移 −0.0407 s，没有漂移
- 项目 01：拼接版 = 方案三 0–67.8 s + 方案四（偏移 +67.93 s）
- 项目 03：分段视频相对转写音轨的偏移为 10.7 ms，逐个分段验证过
