## 请留意

- **口号段的逐字时间是手工定的**（前奏、两段 Hook、Build、Drop、尾奏的歌名）：合唱叠在主唱上，强制对齐器在这些段落失灵。依据是转写的词时间、人声起音和频谱图，没有人听过。Hook 里唱得较长的几个字（每句后半句）最没把握。
- **前奏 8.2–12.2 s** 判断为同一句唱了两遍（先慢后快），依据是音节数和转写；如果第一遍其实是别的内容，画面上会多出一遍这句歌词。
- **Drop 的后两行录音里没有唱**（转写、起音和对齐都没有找到）。它们以上下两条滚动的行情带出现，不和演唱同步。
- 新闻采样（1.6–3.0 s）语速很快，三个词的时间是按频谱图上的音节估的。
- 画面排到了接近满幅。在抖音 / TikTok 里，最下面约 15% 和右侧一列会被平台的文案和按钮盖住一部分。

## 关键制作步骤

1. **量歌。** 75.00 BPM，整首不漂，小节线在 3.2 s 的整数倍上；五处无鼓；尾段 Hook 是第一段的原样重复（间隔 198.40 s）；Drop 每小节重复。每一项对应到画面上的一个决定，见 storyboard 第 1 节。
2. **定规则。** 实心 = 回来了的，空心 = 还没回来的；呼应句 = 反色块。见 storyboard 第 2 节。
3. **排版引擎。** `typo.py` 把歌词单的每一行拆成"显示词元"（一个汉字或一个英文词，连同挂在它上面的标点），逐行断言和歌词单一致；`set_block` 把每一行排到撑满给定的框（海报式），字号由行宽决定，所以单独成行的词自动变成巨字。`kit.py` 是字形缓存、仿射贴图和整帧后期（推镜、色散、辉光、撕裂、扫描线、颗粒）。
4. **每个段落一种材质**（`look_*.py`）：唱片和通讯带（前奏 / 尾奏）、绿黑海报（Hook）、剪贴报纸（主歌一 / 三）、行情屏（主歌二）、负片和满屏数字（Build）、彩色放射光（Drop）、暖光宋体（Bridge）。
5. **跟鼓。** `feat.py` 从分离出的伴奏里取底鼓 / 军鼓 / 踩镲的起音包络，`beat.py` 做成带衰减的包络；所有推镜、震动、色散、撕裂读它。
6. **逐字时间。** 主歌用 CTC 强制对齐的四种估计取中位数；口号段手工定。见 storyboard 第 4 节。
7. **音轨不动。** 原曲 MP3 流原样复制进 mp4。

## 复盘

**做得好**
- 先量再想又一次给出了最省力的路：尾段 Hook 原样重复、Drop 每小节重复，这两处量出来之后，最难定时的口号段只需要手工定一份。
- "呼应句"没有做成第二种颜色的字幕，而是一个动作（从另一侧砸回来），和全片的规则是同一件事。
- 分行就是设计：把一个词单独放一行，它就自动变成巨字，不需要逐句写特例。

**踩坑 / 注意**
- 通用的拍点拟合把 75 BPM 量成了 71.2；起音直方图（对 0.2 s 取模）一眼就能看出真实网格。
- 逐句强制对齐依赖粗略起止：转写覆盖率低的句子窗口给窄了，后半句全部挤在一起。整段一次性对齐作为第二意见能把它们找出来。
- 转写在口吃段（"ready ready ready……"）陷入循环；这反而提示了那里有十几次重复，再用起音列表定每一次的时间。
