## 过程中遇到的情况

| # | 情况 | 怎么处理的 |
|---|---|---|
| 1 | 没有图片 / 视频生成 API，也没有云端转写 API | 画面全部由程序计算（numpy / OpenCV / Pillow）；识别和对齐全部用本机 CPU 上的模型（faster-whisper medium、MMS 对齐模型、UVR 人声分离） |
| 2 | 通用的结构分析脚本把速度量成 71.2 BPM，另一个量成 75 / 150 | 用分离出的伴奏做底鼓 / 军鼓起音直方图：对 0.2 s 取模只有一个尖峰，速度是整 75.00 BPM，小节线在 3.2 s 的整数倍上 |
| 3 | 强制对齐在所有口号段（前奏、Hook、Build、Drop）失灵，路径后验低于 0.05 | 这些段落手工定时：转写词时间 + 人声起音列表 + 频谱图。量到尾段 Hook 是第一段的原样重复（间隔 198.40 s），Drop 每小节重复，手工定的时间因此只需要定一份 |
| 4 | 录音和歌词单不完全一样：三句唱了两遍；Drop 只反复唱前两行，后两行没有唱；"Ready?" 和 Hook 结尾的 "back" 有十几次口吃式重复 | 唱了两遍的句子出现两遍（第二遍反色）。没唱的两行作为 Drop 里的滚动行情带出现，不假装和演唱同步。口吃的词不加字，同一个词在每一次重复上再砸一次 |
| 5 | 主歌里逐句对齐和整段对齐在个别句子上相差 1 秒以上 | 四种估计（逐句、整段人声轨、整段混音、转写词时间）取中位数；把相差超过 0.2 s 的字全部打印出来看，确认每一处都是某一种估计整体跑偏 |

## 拆解

1. **"超级吸引眼球……不要停在静态背景加滚动字幕"**：没有给风格，给的是下限和目标。做法是把每一行都排到撑满画面宽度（海报式排版），一句一个画面，每个字在被唱出的那一帧砸出来；背景是程序画的材质，跟着量到的鼓动。
2. **"方括号……可以用来安排视觉上的风格切换"**：11 个段落标注里的编曲词（old school boom bap、trap triplet flow、EDM supersaw、piano only……）各对应一种材质：剪贴报纸、行情屏、满屏放射光、一盏暖光。主歌三的标注是两种鼓的混合，画面就是两种材质的混合。
3. **"圆括号里的是呼应句"**：呼应句不是另一种颜色的字幕，而是从另一侧砸回来的反色块 / 整幅负片。圆括号本身保留在画面上（"歌词文字原样使用"）。
4. **"歌词文字原样使用，中英混排保持不变"**：做成了可检查的条件。排版前的分词模块逐行断言"屏幕上的字符串 = 歌词单这一行去掉空格后的字符串"，74 行全部通过；大小写不改（Drop 的大写是歌词单自己写的）。破折号画成一条横线。
5. **"跟着演唱逐句同步出现，并踩在节拍上"**：两件事分开做。字的出现时间跟人声（逐字对齐）；画面的冲击（推镜、震动、色散、撕裂）跟伴奏里量到的鼓。
6. 画面里统一的那条规则（实心 = 回来了的，空心 = 还没回来的）不是提示词要求的，是从歌词的转折里取的，见 [storyboard.md](storyboard.md) 第 2 节。
